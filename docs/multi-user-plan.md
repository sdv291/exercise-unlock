# Несколько пользователей — план

Статус: этап 1 сделан в 1.5.0 (2026-11-12), этапы 2 и 3 впереди.
1.5.0 ставится с нуля: обратной совместимости с 1.4.x нет (старый `state.dat`
не читается, протокол плитки и службы изменился). Перед установкой 1.5.0 —
«Видалити все» в установщике 1.4.x и перезагрузка.

## Как устроено

- **Пользователь — это учётная запись Windows** из `data\users.allow` (по
  одной на строку, UTF-8). Плитка Exercise Unlock появляется только у них.
  Пароль каждой хранится в хранилище (`vault.dat`) под её именем.
- **Правила: общие + личные.** `[reward]` и `[schedule]` в `config.ini` — для
  всех. `[reward@<имя>]` и `[schedule@<имя>]` меняют отдельные ключи для одной
  учётной записи, остальное — как для всех (`Config::Rules(account)`,
  `UserRules`). В одном слое ключи пробуются по порядку: у кого задан только
  свой `active_from`, у того он действует и в будни, даже если у всех есть
  `weekday_from`.
- **Активный пользователь.** Каждый запрос плитки к службе несёт имя своей
  учётной записи (`Ipc::Request::user`, протокол v2). Служба делает её
  активной (`SelectUser`): счётчики, «банк», пауза сессии, день — поля `State`
  — принадлежат активному, остальные ждут в своих записях. Чужая идущая
  сессия перед переключением ставится на паузу, как при блокировке. Плитка
  опрашивает службу, только пока выбрана, поэтому повторы до выбора своей
  плитки идут прежнему активному.
- **`state.dat` v6**: заголовок (активный, его сессия, дата установки) и
  запись на каждого пользователя.
- **Калибровка пока общая** (этап 2).

## Этап 1 — сделано (1.5.0)

1. `Config::Rules` / `UserRules`: награды, лимиты, расписание по пользователю.
2. `State`: записи по пользователям, `SelectUser`, `ActiveRules`,
   `IsWithinHoursNow` (детекторы, телефон); `state.dat` v6.
3. Протокол v2 (имя в запросе); `PipeServer` переключает пользователя.
4. Плитка: имя учётной записи у каждой, свой пароль из хранилища, своё
   имя в запросах.
5. Сессии (`SessionManager`), телефон (`PhoneLink`) — по правилам активного.
6. Окно настроек: «Для кого» на страницах «Час» и «Розклад» (пустое поле —
   как для всех, серым — их значение); страница «Користувачі»: добавить
   учётную запись с проверкой пароля Windows, удалить (последнюю нельзя).
   Добавленной ставится запрет смены пароля, если включена блокировка.
7. Установщик: `users.allow` сохраняет добавленных в настройках; блокировка
   и её отмена при удалении — для всех из списка; ярлык «Налаштування
   Exercise Unlock»; удалены переносы данных со старых версий.
8. `tools\test-pipe.ps1 -User <имя>`; калибратор `/users <файл>` (для
   разработчика: другой список пользователей в настройках).

Проверено: логика правил, переключения и `state.dat` — тестом против
исходников службы (21 проверка); окно настроек и диалог добавления — на
копии калибратора без повышения прав. Не проверено на реальном экране
блокировки с несколькими учётными записями.

## Этап 2 — личная калибровка (~4 дня)

- `[squat@<имя>]`, `[pushup@<имя>]`, `[situp@<имя>]`, `[phone_*@<имя>]` —
  те же слои, что у правил; `Config::Squat(account)` и т. д.
- Детекторы вебкамеры получают пороги активного пользователя при его смене
  (сброс фазы детектора, чтобы начатый повтор не ушёл другому).
- Калибратор: «Для кого калібрування» на первом шаге, запись в личные секции;
  проверка повторами — с его порогами; калибровка через телефон тоже.
- Окно настроек: «Для кого» и на страницах упражнений.

## Этап 3 — доводка (~3 дня)

- Быстрая смена пользователей: время одного кончилось, пока за ПК другой —
  блокировать сеанс того, чья сессия, а не текущий консольный.
- `activity.log` и dashboard с именем пользователя.
- Проверка паролей всех пользователей при обновлении (сейчас — только
  основного); в настройках — пометка «пароль больше не подходит».
